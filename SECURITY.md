# Security Policy

## Reporting a vulnerability

Please **do not open a public issue** for a security vulnerability.

Instead, email **contact@indiegoweb.com** with:

- A description of the issue and its potential impact
- Steps to reproduce, or a proof of concept if you have one
- The affected repo and version/commit

You should get a response within a few days. Once a fix is confirmed, we'll coordinate on disclosure timing with you before anything is made public.

## Supported versions

These are solo-maintained open-source projects. In general, only the **latest published version** of each package receives security fixes — there's no backport policy across older major versions unless a specific repo's own docs say otherwise.

## Scope

This applies to every repo under [whybothercoding](https://github.com/whybothercoding) that doesn't have its own `SECURITY.md`. If a repo has its own, that one takes precedence.
